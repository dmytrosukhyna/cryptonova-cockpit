# Система отделов (агентов) — 12.10.2026

```
            ┌──────────────┐
 BingX/Binance ─▶│ Квант-отдел  │ детерминированный: режимы, зоны, сетапы, деривативы, портфельный слой
            └──────┬───────┘
 RSS (5 источн.) ─▶│ Отдел новостей │ сборщик → LLM-аналитик → ЖУРНАЛ ПРОГНОЗОВ → оценка по факту (калибровка)
            └──────┬───────┘
 CoinGecko ──────▶│ Фундаментал   │ MCap, FDV, саплай/разлоки, объём/капа, коммиты → флаги red/amber/green
            └──────┬───────┘
            ┌──────▼───────┐
            │ Риск-офицер   │ вето: блэкаут по новостям, режим BTC, корреляция, лимиты, свежесть данных
            └──────┬───────┘
            ┌──────▼───────┐
            │ Оркестратор   │ собирает decision.json; Редактор (LLM) пишет пост ТОЛЬКО из этого JSON
            └──────┬───────┘
                   ▼  web/decision.json → терминал;  --send → Telegram
```

Принципы:
- Числа считает только код. LLM интерпретирует новости и формулирует текст; если ключа нет — работает мок по
  ключевым словам и пост пишется правилами. Ничего не ломается без API.
- Оценка новости = прогноз: актив, категория, направление, горизонт, сила 1–5, уверенность, механизм, «что подтвердит».
  Через горизонт прогноз сверяется с фактической ценой; по категориям копится таблица «угадано/Brier/средний ход».
  Так «что на что влияет» становится измеренным знанием системы, а не мнением.
- Риск-офицер имеет право вето над любым сигналом и объясняет причину в одну строку.

## Запуск
```bash
export CNQ_LLM_PROVIDER=groq          # groq (бесплатно, по умолчанию) | gemini | openrouter | anthropic
export CNQ_LLM_KEY=...                # без него — мок
export CNQ_LLM_MODEL=openai/gpt-oss-120b   # необязательно, у провайдера есть модель по умолчанию
python -m cnq.cli terminal --out web  # квант-слой
python -m cnq.cli agents --out web --send   # отделы → web/decision.json, пост в Telegram
```
Cron: `agents` раз в час (новости/риск), `brief`/`agents --send` в 06:00 UTC.
