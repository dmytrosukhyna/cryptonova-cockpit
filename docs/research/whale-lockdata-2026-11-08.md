# Уход кита по «нет данных больше суток» — разбор (п. 111), 08.11.2026

**Вопрос.** 07.11 кит 乾坤策略量化 ушёл из закреплённого списка с причиной «нет данных о ките больше суток», 3 его копии закрыты
(реально −$11.64, на столе −$36.34). 08.11 в той же зоне 慢就是快Mike8. Кит пропал или это наш сбор данных?

**Что нашли (код + whales_top.json, 08.11 13:15 UTC).**
- Кандидаты Binance берутся раз в сутки из открытого рейтинга: ~260 портфелей → P&L > 0 и win ≥ 70% по цифре Binance → видимые позиции →
  **первые 35 по 30-дневному P&L** (`BN_PRE_N = 35`). Изучаются только они.
- Кит закреплённого списка, выпавший из этих 35 (просто потому, что другие заработали за 30 дней больше), не изучается вовсе.
  `follow_lock.passing` перестаёт обновляться, и через 24 ч правило замка `lock_hard` уводит его как «нет данных», а стол закрывает копии.
- 慢就是快Mike8: последний «проходит» 16,9 ч назад, в текущем срезе (top/others) его нет → без исправления выбыл бы около 22:20 Афин 08.11 (последний «проходит» 07.11 20:19 UTC),
  до пересмотра 09.11. Открытых копий у него сейчас нет.
- 乾坤策略量化: последний «проходит» 40,9 ч назад — та же картина (последний «проходит» 06.11 20:20 UTC, убран 07.11 20:33 UTC).

**Вывод.** Причина «нет данных» срабатывала не на отсутствие данных, а на предел среза. Это ошибка сбора, не свойство кита:
данные одного кита — 2–4 запроса.

**Исправление (08.11, тест в tests/test_whale_study.py).** `whale_study.locked_rows`: киты закреплённого списка, которых нет среди
кандидатов дня, изучаются по адресу из сохранённой строки (Binance и OKX), причём первыми в очереди бюджета. Правила не менялись:
тот же 60-дневный отбор; между пересмотрами кит уходит только по жёстким причинам (скрыл позиции, 60 дней в минусе, −10% доли на столе,
данных реально нет > 24 ч); на пересмотре изученный и не прошедший отбор кит уходит, как и раньше.

**Что не проверено честно.** Ретро-сравнение «закрыть копии по правилу» против «выйти вместе с китом» для 乾坤 сделать нельзя:
